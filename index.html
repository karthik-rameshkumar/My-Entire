The developer problem

Your agent forgot everything

An hour of exploration. Dozens of tools. Three hidden constraints. Two corrections. The right change, finally.

Then you close the session — and none of it follows you.

Every new session is the agent’s first day on the project.

The developer problem

Git stores the result, not the process

Git answers

$ git log --oneline
a3f9c12 What changed? ✓
a3f9c12 Who committed it? ✓
a3f9c12 When did it happen? ✓

Agentic development asks

  • What task was this change trying to accomplish?
  • Which agent and session produced it?
  • Why was this approach selected, and what was tried before?
  • What did the developer correct?
  • Can another agent continue the work?
  • Why does this particular line exist?

If the code is worth versioning, the context that produced it is worth versioning too.

The developer problem

Agent history is fragmented

You already use more than one agent. Each tool keeps its own partial history, in its own silo.

The developer harness

Composable primitives, not one prescribed workflow

⌘

Trails

give work a home

  • A task item linked to exactly one branch
  • Gathers intent, sessions, Checkpoints, attempts, decisions, evaluations
  • The living context while humans and agents work
▷

Runners

ask questions about the work

  • Repo-defined agent evaluations: config lives in the repository, like an Actions workflow
  • Runs ephemerally over code, intent, sessions, or a whole Trail
  • Returns an outcome; it doesn’t block anything by itself
⛨

Gates

decide the consequence

  • Enhanced branch protection
  • Can use a Runner outcome to block, require review, allow, or trigger a workflow
  • Or leave outcomes as informational health signals

Standalone by design: a Trail needs no Runners, a Runner needs no Trail, a Runner outcome doesn’t have to become a Gate. Combine them however you want.

The developer harness

Make it concrete

Trail

Replace the rate limiter without changing the public API

feature/rate-limiter
▷ task-completeness Did the implementation achieve the requested outcome? health indicator
▷ api-compatibility Has the public API changed? failure blocks
▷ performance Does it perform better under the expected load? uncertain → review
▷ friday-5pm Would you merge this at 5pm on a Friday? uncertain → review

Entire doesn’t decide what “good” means. The developer defines it, and stays in control of the harness.

The infrastructure underneath

Agents create a different Git workloadpreview

  • Runners and ephemeral environments mean more clones and fetches
  • More parallel branches, higher read/write concurrency
  • More demand for regional performance

Entire’s distributed Git network mirrors repositories into regional cells built for agent-scale traffic, while you keep using GitHub.

Git was designed to be distributed. Agentic development is our chance to make software infrastructure open and distributed again.
